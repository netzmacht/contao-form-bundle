# Quality assurance runs through phpcq

Every test run, static analysis and coding-style check in this project goes
through **phpcq**. phpcq installs and invokes the underlying tools itself. Its
configuration lives in `.phpcq.yaml.dist`, which is generated by Companion:
`phpcq.plugins` lists the tools in use, `tasks` the chains they run in.

## Rules

- Never install a quality tool separately. There is no `vendor/bin/phpunit`,
  `vendor/bin/psalm` or `vendor/bin/phpcs` here and none should be added —
  `composer require --dev phpunit/phpunit` and friends are wrong in this
  project.
- Run the full chain before reporting work as finished: `vendor/bin/phpcq run`.
  Single tasks are for narrowing down a problem, never a substitute for the
  chain.
- Never skip part of the chain because it looks unrelated to your change. If a
  task fails for reasons outside it, say so — do not drop it.
- To change which tools run, change the `tools.phpcq` block in `companion.json`
  (or the receipt it comes from) and re-run Companion's `project:configure`.
- To read and fix diagnostics, use the `phpcq` skill if it is
  available: it documents the report workflow and carries per-diagnostic
  fix instructions. It is installed per developer, not shipped with this
  project — install it with Companion's `claude-code:install-skills`.

## Commands

| Command | Effect |
| --- | --- |
| `vendor/bin/phpcq run` | Runs the default chain — the full check |
| `vendor/bin/phpcq run <chain\|task>` | Runs one chain or one task, see `tasks` in `.phpcq.yaml.dist` |
| `vendor/bin/phpcq run --threshold=marginal` | Writes the file report `.phpcq/build/file-report.xml` that the diagnostics workflow reads |
| `vendor/bin/phpcq exec phpunit -- --filter=name tests/FooTest.php` | Calls a tool directly, bypassing the pipeline |
